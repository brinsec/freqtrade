    运行 FreqAI¶

    有两种训练和部署自适应机器学习模型的方法 - 实盘部署和历史回测。在这两种情况下，FreqAI 运行/模拟模型的定期重训练，如下图所示：

    实盘部署¶

    可以使用以下命令在模拟/实盘模式下运行 FreqAI：

    freqtrade trade --strategy FreqaiExampleStrategy --config config_freqai.example.json --freqaimodel LightGBMRegressor

    启动时，FreqAI 将根据配置设置开始训练一个新模型，并带有新的 identifier。训练完成后，模型将用于对传入蜡烛进行预测，直到有新模型可用。新模型通常尽可能频繁地生成，FreqAI 管理交易对的内部队列，以尝试保持所有模型同样最新。FreqAI 将始终使用最近训练的模型对传入的实时数据进行预测。如果您不希望 FreqAI 尽可能频繁地重训练新模型，可以设置 live_retrain_hours 来告诉 FreqAI 在训练新模型之前至少等待该小时数。此外，您可以设置 expired_hours 来告诉 FreqAI 避免对超过该小时数的模型进行预测。

    默认情况下，训练好的模型保存到磁盘，以便在回测期间或崩溃后重用。您可以选择清除旧模型以节省磁盘空间，方法是在配置中设置 "purge_old_models": true。

    要从保存的回测模型（或从以前崩溃的模拟/实盘会话）启动模拟/实盘运行，您只需要指定特定模型的 identifier：

        "freqai": {
        "identifier": "example",
        "live_retrain_hours": 0.5
    }

    在这种情况下，虽然 FreqAI 将使用预训练模型启动，但它仍会检查自模型训练以来已经过了多长时间。如果自加载模型结束以来已经过了完整的 live_retrain_hours，FreqAI 将开始训练新模型。

    自动数据下载¶

    FreqAI 自动下载确保通过定义的 train_period_days 和 startup_candle_count 训练模型所需的适当数量的数据（有关这些参数的详细描述，请参阅参数表）。

    保存预测数据¶

    在特定 identifier 模型的生命周期内进行的所有预测都存储在 historic_predictions.pkl 中，以便在崩溃或更改配置后重新加载。

    清除旧模型数据¶

    FreqAI 在每次成功训练后存储新模型文件。这些文件会随着生成新模型以适应新市场条件而变得过时。如果您计划让 FreqAI 在高频重训练的情况下长时间运行，您应该在配置中启用 purge_old_models：

        "freqai": {
        "purge_old_models": 4,
    }

    这将自动清除所有比最近训练的四个模型更旧的模型以节省磁盘空间。输入"0"将永远不会清除任何模型。

    回测¶

    FreqAI 回测模块可以使用以下命令执行：

    freqtrade backtesting --strategy FreqaiExampleStrategy --strategy-path freqtrade/templates --config config_examples/config_freqai.example.json --freqaimodel LightGBMRegressor --timerange 20210501-20210701

    如果此命令从未使用现有配置文件执行过，FreqAI 将为每个交易对、在扩展的 --timerange 内的每个回测窗口训练一个新模型。

    回测模式需要在部署前下载必要的数据（与 FreqAI 自动处理数据下载的模拟/实盘模式不同）。您应该仔细考虑下载数据的时间范围大于回测时间范围。这是因为 FreqAI 需要所需回测时间范围之前的数据，以便训练模型准备好对设定回测时间范围的第一个蜡烛进行预测。有关如何计算要下载的数据的更多详细信息可以在这里找到。

    模型重用

    一旦训练完成，您可以使用相同的配置文件再次执行回测， FreqAI 将找到训练好的模型并加载它们，而不是花费时间训练。如果您想调整（甚至超参数优化）策略内的买入和卖出条件，这很有用。如果您 想使用相同的配置文件重训练新模型，您应该简单地更改 identifier。 这样，您可以通过简单地指定 identifier 返回到使用任何您希望的模型。

    注意

    回测为每个回测窗口调用一次 set_freqai_targets()（其中窗口数是完整回测时间范围除以 backtest_period_days 参数）。这样做意味着目标模拟模拟/实盘行为而没有前瞻偏差。但是，feature_engineering_*() 中的特征定义在整个训练时间范围上执行一次。这意味着您应该确保特征不会向前看未来。 有关前瞻偏差的更多详细信息可以在常见错误中找到。

    保存回测预测数据¶

    为了允许调整您的策略（不是特征！），FreqAI 将自动保存回测期间的预测，以便它们可以在使用相同 identifier 模型的未来回测和实盘运行中重用。这提供了旨在启用入场/出场标准的高级超参数优化的性能增强。

    将在 unique-id 文件夹中创建一个名为 backtesting_predictions 的附加目录，其中包含所有以 feather 格式存储的预测。

    要更改您的特征，您必须在配置中设置新的 identifier 以向 FreqAI 发出信号以训练新模型。

    要保存特定回测期间生成的模型，以便您可以从其中一个启动实盘部署而不是训练新模型，您必须在配置中将 save_backtest_models 设置为 True。

    注意

    为了确保模型可以重用，freqAI 将使用长度为 1 的 dataframe 调用您的策略。 如果您的策略需要比这更多的数据来生成相同的特征，您不能将回测预测重用于实盘部署，并且需要为每个新回测更新您的 identifier。

    回测实盘收集的预测¶

    FreqAI 允许您通过回测参数 --freqai-backtest-live-models 重用实盘历史预测。当您想重用模拟/运行中生成的预测进行比较或其他研究时，这可能很有用。

    --timerange 参数不必提供，因为它将通过历史预测文件中的数据自动计算。

    下载数据以覆盖完整回测期间¶

    对于实盘/模拟部署，FreqAI 将自动下载必要的数据。但是，要使用回测功能，您需要使用 download-data 下载必要的数据（详细信息在这里）。您需要仔细注意了解需要下载多少额外数据，以确保在回测时间范围开始之前有足够的训练数据。额外数据的数量可以通过将时间范围的开始日期向后移动 train_period_days 和 startup_candle_count（有关这些参数的详细描述，请参阅参数表）从所需回测时间范围的开始大致估算。

    例如，要回测 --timerange 20210501-20210701，使用将 train_period_days 设置为 30 的示例配置，加上最大 include_timeframes 为 1h 的 startup_candle_count: 40，下载数据的开始日期需要是 20210501 - 30 天 - 40 * 1h / 24 小时 = 20210330（比所需训练时间范围的开始早 31.7 天）。

    决定滑动训练窗口和回测持续时间的大小¶

    回测时间范围在配置文件中使用典型的 --timerange 参数定义。滑动训练窗口的持续时间由 train_period_days 设置，而 backtest_period_days 是滑动回测窗口，两者都以天数计算（backtest_period_days 可以是浮点数，以在实盘/模拟模式中指示子日重训练）。在给出的示例配置（在 config_examples/config_freqai.example.json 中找到）中，用户要求 FreqAI 使用 30 天的训练期并在随后的 7 天进行回测。模型训练后，FreqAI 将回测随后的 7 天。然后"滑动窗口"向前移动一周（模拟 FreqAI 在实盘模式中每周重训练一次），新模型使用前 30 天（包括前一个模型用于回测的 7 天）进行训练。这重复直到 --timerange 结束。这意味着如果您设置 --timerange 20210501-20210701，FreqAI 将在 --timerange 结束时训练 8 个单独的模型（因为完整范围包括 8 周）。

    注意

    虽然允许小数 backtest_period_days，但您应该知道 --timerange 除以该值以确定 FreqAI 需要训练的模型数量以完成完整范围的回测。例如，通过设置 10 天的 --timerange 和 0.1 的 backtest_period_days，FreqAI 将需要为每个交易对训练 100 个模型以完成完整回测。因此，FreqAI 自适应训练的真实回测将花费非常长的时间。完全测试模型的最佳方法是运行模拟并让它持续训练。在这种情况下，回测将花费与模拟运行完全相同的时间。

    定义模型过期时间¶

    在模拟/实盘模式下，FreqAI 按顺序训练每个交易对（在与主 Freqtrade 机器人分开的线程/GPU 上）。这意味着模型之间总是存在年龄差异。如果您在 50 个交易对上训练，每个交易对需要 5 分钟训练，最旧的模型将超过 4 小时。如果策略的特征时间尺度（交易持续时间目标）小于 4 小时，这可能是不希望的。您可以通过在配置文件中设置 expiration_hours 来决定仅在模型小于特定小时数时进行交易入场：

        "freqai": {
        "expiration_hours": 0.5,
    }

    在给出的示例配置中，用户将只允许对小于 ½ 小时的模型进行预测。

    控制模型学习过程¶

    模型训练参数对于所选机器学习库是唯一的。FreqAI 允许您使用配置中的 model_training_parameters 字典为任何库设置任何参数。示例配置（在 config_examples/config_freqai.example.json 中找到）显示了与 Catboost 和 LightGBM 相关的一些示例参数，但您可以添加这些库或您选择实现的任何其他机器学习库中可用的任何参数。

    数据分割参数在 data_split_parameters 中定义，可以是与 scikit-learn 的 train_test_split() 函数相关的任何参数。train_test_split() 有一个名为 shuffle 的参数，允许打乱数据或保持不打乱。这对于避免使用时间自相关数据偏置训练特别有用。有关这些参数的更多详细信息可以在 scikit-learn 网站（外部网站）上找到。

    FreqAI 特定参数 label_period_candles 定义用于 labels 的偏移（未来的蜡烛数）。在给出的示例配置中，用户要求未来 24 个蜡烛的 labels。

    持续学习¶

    您可以通过在配置中设置 "continual_learning": true 来选择采用持续学习方案。通过启用 continual_learning，在从头开始训练初始模型后，后续训练将从先前训练的最终模型状态开始。这为新模型提供了先前状态的"记忆"。默认情况下，这设置为 False，这意味着所有新模型都从头开始训练，没有来自先前模型的输入。

    持续学习强制恒定的参数空间

    由于 continual_learning 意味着模型参数空间不能在训练之间更改，当启用 continual_learning 时，principal_component_analysis 会自动禁用。提示：PCA 会更改参数空间和特征数量，在这里了解更多关于 PCA 的信息。

    实验性功能

    请注意，这目前是增量学习的简单方法，当市场远离您的模型时，它有很大的概率过度拟合/陷入局部最小值。我们在 FreqAI 中提供这些机制主要是为了实验目的，以便它准备好用于在像加密市场这样的混沌系统中进行持续学习的更成熟方法。

    超参数优化¶

    您可以使用与典型的 Freqtrade 超参数优化相同的命令进行超参数优化：

    freqtrade hyperopt --hyperopt-loss SharpeHyperOptLoss --strategy FreqaiExampleStrategy --freqaimodel LightGBMRegressor --strategy-path freqtrade/templates --config config_examples/config_freqai.example.json --timerange 20220428-20220507

    hyperopt 要求您以与进行回测相同的方式预先下载数据。此外，在尝试对 FreqAI 策略进行超参数优化时，您必须考虑一些限制：

    • --analyze-per-epoch 超参数优化参数与 FreqAI 不兼容。
    • 不可能在 feature_engineering_*() 和 set_freqai_targets() 函数中对指标进行超参数优化。这意味着您不能使用超参数优化来优化模型参数。除了此例外，可以优化所有其他空间。
    • 回测说明也适用于超参数优化。

    结合超参数优化和 FreqAI 的最佳方法是专注于超参数优化入场/出场阈值/标准。您需要专注于超参数优化未在特征中使用的参数。例如，您不应该尝试在特征创建中超参数优化滚动窗口长度，或 FreqAI 配置中改变预测的任何部分。为了有效地超参数优化 FreqAI 策略，FreqAI 将预测存储为数据框并重用它们。因此，要求仅超参数优化入场/出场阈值/标准。

    FreqAI 中可超参数优化参数的一个很好的例子是差异指数 (DI) DI_values 的阈值，超过该阈值我们认为数据点是异常值：

    di_max = IntParameter(low=1, high=20, default=10, space='buy', optimize=True, load=True)
dataframe['outlier'] = np.where(dataframe['DI_values'] > self.di_max.value/10, 1, 0)

    此特定的超参数优化将帮助您了解适合您特定参数空间的 DI_values。

    使用 Tensorboard¶

    可用性

    FreqAI 为多种模型包括 Tensorboard，包括 XGBoost、所有 PyTorch 模型、强化学习和 Catboost。如果您希望看到 Tensorboard 集成到另一种模型类型中，请在 Freqtrade GitHub 上打开一个问题

    要求

    Tensorboard 日志记录需要 FreqAI torch 安装/docker 镜像。

    使用 tensorboard 的最简单方法是在配置文件中确保 freqai.activate_tensorboard 设置为 True（默认设置），运行 FreqAI，然后打开单独的 shell 并运行：

    cd freqtrade
tensorboard --logdir user_data/models/unique-id

    其中 unique-id 是 freqai 配置文件中设置的 identifier。如果您希望在浏览器中 127.0.0.1:6060（6060 是 Tensorboard 使用的默认端口）查看输出，则必须在单独的 shell 中运行此命令。

    停用以提高性能

    Tensorboard 日志记录可能会减慢训练速度，应在生产使用中停用。
